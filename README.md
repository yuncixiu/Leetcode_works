# 排序问题
## 一.插入排序:
1.直接插入排序 思路 -> 可以比较成摸牌，不过要从1序列开始摸牌(因为第0序列默认成已经排好序的).第二步，就是比较目前摸到的牌和之前摸到的牌的大小，如果目前摸到的牌大，就什么也不做，如果摸到的牌小，就从当前的牌的前一个开始遍历，一直到摸到的牌大于前面的牌。  注意：不要一遍遍历一边比较牌的大小，可以用一个更巧妙的方法，就是在[找到左边的元素小于当前摸到的元素之前，把所有的元素右移] 
是否稳定:稳定
时间复杂度:O(n**2)  
2.折半插入排序 思路 -> 直接插入排序的寻找元素是全部都进行遍历，举个例子，数组[1,3,5,7,2,9] 进行简单插入排序的话,我们先遍历整个数组，找到2，然后往前遍历 7->5->3，在3前面插入2.仔细想想，7 5 3是不是一个有序数组，对于一个有序数组找元素，最常用的不是挨个遍历(时间复杂度O(n)),而是用二分查找(O(logn))
ps:这个只是优化查找，实际上后移元素一点没变化，可以拓展一下思路，不值得死记住这个代码
是否稳定:稳定
时间复杂度:O(n**2)
3.希尔排序(神中神，时间复杂度可以压缩到O(n**1.3)，写起来也很简单，只不过没有快速排序和归并排序快)
希尔排序的核心思路就是先让数组变成基本有序，一般采用分割的方法，分割成d份，然后再循环遍历
是否稳定:不稳定
## 二.交换排序
1.冒泡排序
时间复杂度O(n**2)
思路:最简单的排序算法，大数下沉，小数上浮，唯一需要注意的坑就是第二个for循环的起始位置是n-i+1，因为越排序剩余的数组长度就越短
优化:可以提前终止，设置一个flag变量，初始为true,发生交换就变成false，只要不交换就直接break
2.快速排序
时间复杂度 **O(nlogn)**  (顾名思义，这个排序很快速)
思路:先选取一个元素作为基准，比如选取arr[0],然后将数组一分为二，左边的都是小于arr[0]的，右边的都是大于arr[0]的，然后返回这个索引，将左右数组分别再次递归
缺点：容易被大量重复元素风筝，比如数组[3,2,2,2,2,2,2,2,2,2,2,2 ……],时间复杂度瞬间退化成O(n**2)
是否稳定:不稳定
